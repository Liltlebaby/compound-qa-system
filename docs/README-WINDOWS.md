# COMPOUND QA สำหรับคอมเซิร์ฟเวอร์ Windows 10/11

แพ็กนี้ใช้คอม Windows เป็นเซิร์ฟเวอร์จริง มือถือใช้เว็บเบราว์เซอร์ สแกน QR เพื่อเข้าบัญชีประจำจุดอัตโนมัติ ไม่ต้องล็อกอินหรือติดตั้งแอป QA และไม่ต้องมีบัญชี ChatGPT

## โหมด localhost สำหรับแก้ไขระบบ

- เปิด START-LOCAL-DEV.cmd หรือใช้ npm run dev ในโฟลเดอร์นี้
- ครั้งแรกต้องติดตั้งแพ็กเกจพัฒนาด้วย npm install (สคริปต์ .cmd ทำให้เมื่อยังไม่มี node_modules)
- เปิด http://localhost:5173/?demo=1 เพื่อทดลองหน้าจอ หรือ http://localhost:5173/login เพื่อทดสอบบัญชีพนักงาน
- แก้หน้าจอแล้วเห็นผลทันที ไม่ต้อง build หรือเผยแพร่ขึ้น Sites ทุกรอบ
- API อยู่บน loopback พอร์ต 3001 และใช้ข้อมูลแยกใน data-dev ไม่แตะฐานข้อมูลใช้งานจริงใน data
- โหมดพัฒนาปิดการลงทะเบียน service worker เพื่อให้แก้หน้าจอแล้วเห็นรุ่นล่าสุด
- โหมดติดตั้งใช้งานจริงยังเปิดผ่าน START-SERVER.cmd ตามเดิม

## สแกน QR จากมือถือระหว่างปรับแต่ง

1. คอมและมือถือต้องเชื่อม Wi-Fi / เครือข่ายเดียวกัน และคอมต้องเปิด npm run dev ค้างไว้
2. เปิดเมนู QR ประจำจุดบนคอม หรือ http://localhost:5173/?demo=1&view=qr
3. ระบบเลือก IP ของคอมอัตโนมัติ เช่น http://192.168.1.50:5173 แทน localhost
4. สแกน QR ของจุดที่ต้องการด้วยกล้องมือถือ เข้าฟอร์มของโรง กะ และจุดนั้นทันที ไม่ต้องเลือกโรงหรือกะ
5. QR ที่เปิดจากโหมดสาธิตยังเป็นข้อมูลทดลอง หากใช้ข้อมูลจริงให้หัวหน้าเลือกเริ่มใช้งานจริงและพิมพ์ QR จากโหมดจริง ข้อมูลสาธิตเก็บแยกในแต่ละเบราว์เซอร์
6. หาก Windows Firewall บล็อก ให้เปิด scripts/windows/ENABLE-MOBILE-ACCESS.ps1 แบบ Administrator เพื่ออนุญาตเฉพาะเครือข่ายย่อยเดียวกันที่ TCP 5173

ถ้าเปลี่ยน Wi-Fi หรือ IP ให้เริ่มโหมดพัฒนาใหม่และใช้ QR ที่สร้างใหม่ ส่วนการเข้าจากอินเทอร์เน็ตภายนอกยังใช้แนวทาง HTTPS ใน docs/HTTPS-ACCESS.md

## ติดตั้งบนคอมอีกเครื่อง

1. ติดตั้ง **Node.js 24 LTS** จาก https://nodejs.org/en/download
2. แตก ZIP ทั้งโฟลเดอร์ไว้ เช่น C:\COMPOUND-QA หลีกเลี่ยงโฟลเดอร์ชั่วคราวหรือโฟลเดอร์ที่ลบอัตโนมัติ
3. ดับเบิลคลิก **START-SERVER.cmd**
4. บนคอมเซิร์ฟเวอร์ เปิด **http://localhost:3000/login**
5. สร้างชื่อผู้ดูแล ชื่อเข้าสู่ระบบ และรหัสผ่านอย่างน้อย 8 ตัว ระบบไม่มีรหัสผ่านเริ่มต้น
6. เลือกโรงและกะ แล้วตั้งแผนผลิต หน่วย Burner/Biscuit สเปก เป้าราย 30 นาที และผู้รับผิดชอบ
7. ระบบสร้างบัญชีประจำจุดให้เมื่อสแกน QR ใช้งานจริงครั้งแรก แยกตามโรง กะ ไลน์ และจุด QA โดยอัตโนมัติ ไม่ต้องตั้งรหัสผ่านให้ QA แต่ละจุด
8. ตั้งทางเข้า HTTPS ตาม docs/HTTPS-ACCESS.md จากนั้นใส่ URL ถาวรในตั้งค่า → รายงานและการเชื่อมต่อ → ที่อยู่เว็บสำหรับ QR
9. พิมพ์ QR ของแต่ละโรง แล้วทดลองสแกนจากมือถือทั้ง Wi-Fi โรงงานและอินเทอร์เน็ตมือถือก่อนเริ่มใช้งานจริง

**ไฟล์เว็บและเซิร์ฟเวอร์ build มาให้แล้ว** การรันบนเครื่องปลายทางใช้ Node.js ได้เลย ไม่ต้อง npm install ไม่ต้องมี PostgreSQL Server แยก

## อัปเดตข้อมูลข้ามเครื่องแบบเรียลไทม์

- คอมและมือถือเปิดโหมดใช้งานจริงจากเซิร์ฟเวอร์เดียวกัน เมื่อ QA กดยืนยันส่งและเซิร์ฟเวอร์บันทึกสำเร็จ ยอดผลผลิต สถานะจุดตรวจ Alarm และรายงานบนเครื่องอื่นจะอัปเดตอัตโนมัติ
- แถบบนแสดง “เรียลไทม์” เมื่อเชื่อมช่องทางแจ้งการเปลี่ยนแปลงสำเร็จ หากสัญญาณหลุด ระบบเชื่อมต่อใหม่และดึงข้อมูลที่พลาดไป พร้อมทางสำรองตรวจข้อมูลทุก 5 วินาทีเมื่อช่องทางเรียลไทม์ไม่พร้อม
- การอัปเดตไม่ล้างค่าที่กำลังกรอก หากมีผู้อื่นแก้รายการเดียวกัน ระบบยังตรวจเวอร์ชันก่อนยืนยันส่ง
- ทุกครั้งยังตรวจบัญชี โรง กะ และสิทธิ์ผ่าน API ตามเดิม ช่องทางแจ้งการเปลี่ยนแปลงไม่ส่งตัวเลขหรือข้อมูลการผลิตโดยตรง
- โหมดสาธิต (`?demo=1`) เก็บข้อมูลแยกในแต่ละเบราว์เซอร์ จึงไม่ใช้ร่วมข้ามเครื่อง
- หากตั้ง reverse proxy / HTTPS ให้รองรับ `text/event-stream` โดยไม่ buffer เส้นทาง `/api/events`

## เตาที่ปิดในรอบการผลิต

- ในฟอร์มเตาอบ แต่ละเตา A–D มีปุ่ม “เตาปิด” กดแล้วไม่ต้องกรอก PV น้ำหนัก Biscuit และอุณหภูมิก้อนยางของเตานั้น ระบบบันทึกสถานะปิดแยกจากค่าศูนย์
- กดปุ่มเดิมอีกครั้งเพื่อกลับมากรอก หากเพิ่งปิดในฟอร์มเดียวกัน ค่าที่กรอกไว้จะกลับมา ส่วนการเปิดจากรายการที่บันทึกว่าปิดแล้วต้องกรอกค่าตรวจใหม่
- สถานะใช้เฉพาะรอบที่บันทึก ไม่ปิดเตารอบถัดไปโดยอัตโนมัติ ค่าตั้ง SV และเวลาอบยังใช้กติกาเดิม
- รายงานและข้อความแชร์ระบุเตาที่ปิดชัดเจน ไม่สร้าง Alarm ข้อมูลขาดจากค่าตรวจที่ไม่เกี่ยวข้องกับเตาปิด และเก็บเหตุผลไว้ในประวัติเมื่อ Alarm เดิมถูกปิดตามสถานะเตา

## บัญชีประจำจุดจาก QR

- หัวหน้าสร้างผู้ดูแลครั้งแรกและตั้งแผนผลิตก่อนหนึ่งครั้ง จากนั้น QA สแกน QR ใช้งานจริงแล้วเข้าฟอร์มได้ทันที
- มีบัญชีแยกเตาอบ คุณภาพ ผลผลิต หอโรย และ PACK/โกดัง และแยกตามโรง / กะ / ไลน์
- สแกนอีกจุดจะเปลี่ยนเป็นบัญชีของจุดนั้น บัญชีเดิมถูกใช้ซ้ำ ไม่สร้างบัญชีใหม่ทุกรอบ
- รายการส่งและประวัติบันทึกชื่อบัญชีประจำจุด เป็นบัญชีใช้ร่วมกัน ไม่ใช่การยืนยันตัวบุคคล
- แต่ละบัญชีอ่านและกรอกได้เฉพาะขอบเขตของตน ระบบตรวจสิทธิ์ที่เซิร์ฟเวอร์ และเข้าแก้ตั้งค่าหรือแผนผลิตไม่ได้
- หัวหน้าปิดบัญชีประจำจุดได้ในหน้าพนักงานและสิทธิ์ เมื่อปิดแล้ว QR ของจุดนั้นจะเข้าไม่ได้
- บัญชีหัวหน้ายังเข้าสู่ระบบตามปกติ QR ไม่เปิดสิทธิ์ผู้ดูแล และไม่มีรหัสผ่านผู้ดูแลอยู่ใน QR

## ตรวจข้อมูล Min–Max และ Alarm (ตามกฎ ไม่ใช้ AI)

- หัวหน้าเข้า ตั้งค่า → ตรวจข้อมูล / Alarm เพื่อกำหนด Min–Max แยกตามลูกค้า/SO และจุดตรวจ เว้นเกณฑ์ที่ไม่ต้องใช้ได้ และกำหนด Max = 0 ได้
- PO / PRI / MV ใช้เกณฑ์จากสเปกคุณภาพเดิม PRI ที่ไม่มีสเปกไม่ถูกตัดสินเกินเกณฑ์
- ค่าตรงขอบ Min หรือ Max ถือว่าอยู่ในช่วง เวลาอบเปรียบเทียบเป็นนาทีและวินาทีจริง ไม่ใช้ชั่วโมงหรือเลขทศนิยมของนาที
- เกณฑ์ใหม่ใช้กับรอบที่เปิดใหม่ รายงานเดิมและสเปกในรอบเดิมไม่เปลี่ยน
- ช่องจำเป็นที่ไม่มีตัวเลขหรือเลือกไม่เกี่ยวข้องต้องมีคำอธิบายรายช่อง ช่องว่างไม่ถูกแปลงเป็น 0 และคำอธิบายใช้ข้ามการตรวจตัวเลขติดลบ/รูปแบบผิดไม่ได้
- ค่าจริงนอกเกณฑ์แสดงสีแดงและบันทึกได้เมื่อยืนยันข้อสังเกต เมื่อส่งสำเร็จจึงเกิด Alarm ในฐานข้อมูลกลาง
- เมนู Alarm แสดงรายการตามวันผลิต โรง และกะ QA เห็นเฉพาะจุดที่ตนมีสิทธิ์ หัวหน้ารับทราบพร้อมหมายเหตุได้
- รับทราบแล้วยังแสดงว่าผิดเกณฑ์ เมื่อส่งค่าตรวจที่กลับเข้าเกณฑ์ระบบจะปิดเอง หรือหัวหน้าบันทึกวิธีแก้ไขและผลติดตามเพื่อปิด Alarm ได้ โดยเก็บผลตรวจเดิมไว้ หากมีค่าผิดเกณฑ์ใหม่จะเปิด Alarm อีกครั้ง
- ประวัติ Alarm เก็บการเกิด รับทราบ เปิดซ้ำ และแก้ไข การส่งข้อมูลซ้ำไม่สร้าง Alarm ซ้ำ
- แจ้งเตือนภายในเว็บและข้อความบนหน้าจอ ยังไม่เปิดเสียง การแจ้งเตือนนอกเว็บ หรือส่ง WhatsApp อัตโนมัติ
- รายงานและข้อความแชร์เก็บคำอธิบายข้อมูลที่ไม่มีตัวเลข โดยไม่สร้างเหตุผลขึ้นเอง

## โรงงานและกะที่ตั้งไว้

- AJ2: กะเช้า 08:00–19:00 / กะดึก 21:00–08:00 ใช้ QR แยกกะเช้า / กะดึก
- AJ2B: กะเช้า 08:00–19:00 เข้าฟอร์มจุดที่สแกนโดยตรง
- แผน สเปก ผลตรวจ และรายงานแยกตามโรง + กะ + รอบเวลา + SO
- วันที่ผลิตเป็นวันที่เริ่มกะใน Asia/Bangkok เช่น กะดึก 29 ต.ค. รอบ 00:00 ของเช้า 30 ต.ค. ยังเป็นวันที่ผลิต 29 ต.ค.

หน่วย Burner และ Biscuit ยังไม่เดาจากตัวเลขต้นทาง หัวหน้าต้องยืนยันหน่วยก่อนเปิดรอบที่มีจุดเตาอบจริง เป้าต่อรอบ 8 ตันเป็นค่าเริ่มต้นจากตัวอย่าง ต้องตรวจแผนของแต่ละโรงและกะก่อนใช้จริง

## เปิดรอบอัตโนมัติ

- เปิดรอบทุก 30 นาทีตามเวลาไทย ภายในเวลากะที่ตั้งไว้ ไม่ต้องกดเปิดเอง
- AJ2 กะเช้าเปิดรอบแรก 08:00–08:30 รอบสุดท้าย 18:30–19:00 / กะดึกเปิดรอบแรก 21:00–21:30 รอบสุดท้าย 07:30–08:00 ของวันถัดไป
- AJ2B เปิด 08:00–19:00 ไม่มีรอบนอกกะ
- หัวหน้าบันทึกแผนผลิตและยืนยันหน่วยก่อน ระบบเก็บแผน/สเปกของแต่ละรอบไว้ ค่าที่วัดจริงเริ่มว่าง
- ตั้งหรือพักการเปิดรอบที่ ตั้งค่า → แผนผลิตและสเปก → เปิดรอบอัตโนมัติตามเวลากะ แยกแต่ละโรง/กะ
- เซิร์ฟเวอร์ทำงานแม้ไม่มีใครเปิดเว็บ และเปิดรอบปัจจุบันเมื่อเริ่มเครื่องใหม่ ไม่สร้างรอบย้อนหลังตลอดช่วงที่เครื่องดับ
- รอบก่อนที่ข้อมูลยังไม่ครบยังค้างไว้ให้กรอกย้อนหลัง รอบใหม่เปิดตามเวลาโดยไม่รอรอบเก่า
- ปุ่มเปิดรอบย้อนหลัง / เพิ่มเติมไว้สำหรับหัวหน้าแก้สถานการณ์พิเศษ

## ใช้งาน QA

สแกน QR → เข้าสู่ระบบถ้ายังไม่มี session → โรงและกะตาม QR → ตรวจโรง/กะ/วันที่/รอบ/SO → กรอก → ตรวจทาน → ยืนยันส่ง

ผู้มาแทนเวรใช้บัญชีตัวเองและระบุชื่อคนที่แทนได้ ระบบเก็บผู้กรอกจากบัญชีจริง

- ช่องว่างต่างจาก 0 และไม่เกี่ยวข้อง
- ค่านอกสเปกหรือยอด PACK ไม่ตรงยังบันทึกได้ เมื่อยืนยันข้อสังเกต
- SO ผลิต / PACK / โกดัง / defect แยกกัน
- ข้อมูลรอบใหม่ไม่คัดลอกค่าที่วัดจริงจากรอบก่อน
- ถ้าข้อมูลถูกแก้จากอีกเครื่อง ระบบให้ตรวจทานก่อนส่งใหม่
- ข้อมูลรอส่งยังอยู่บนมือถือและต้องกลับมาเข้าบัญชีเดิมเพื่อส่ง
- ใช้ HTTPS สำหรับ QR ถาวร เพื่อให้เปิดหน้าเว็บจาก cache ตอนออฟไลน์ได้ มือถือต้องเปิดเว็บออนไลน์อย่างน้อยครั้งแรก
- ใช้ HTTP ใน LAN ทดสอบการกรอกได้ แต่การเปิดหน้าใหม่/รีโหลดขณะออฟไลน์บนมือถือไม่ได้รับประกัน และไม่ควรใช้ HTTP เป็นทางเข้าจากอินเทอร์เน็ต

## เลือกวันที่และดูย้อนหลัง

- หน้าแรกแสดงรอบเฉพาะวันผลิตปัจจุบัน ไม่ปะปนรอบของวันอื่นในรายการ
- กดปุ่มไอคอนปฏิทินข้างวันที่ เลือกวันที่ผลิต แล้วกด “ดูข้อมูลวันที่เลือก”
- รอบ ผลตรวจ และรายงานจะโหลดเฉพาะวันนั้น สามารถค้นวันเก่าได้โดยไม่จำกัดเฉพาะรอบล่าสุด

## ฐานข้อมูลและสำรอง

ใช้ PostgreSQL เป็นฐานข้อมูลจริง ดูการติดตั้ง ย้าย PostgreSQL เดิม และสำรอง/กู้คืนใน [คู่มือ PostgreSQL](POSTGRESQL.md)

- เครื่องใหม่เปิด `scripts/windows/SETUP-POSTGRESQL.cmd` ครั้งแรกก่อน START-SERVER.cmd
- ข้อมูล local อยู่ใน `.postgres/data` บัญชีและการเชื่อมต่ออยู่ในไฟล์ local ที่ไม่รวมใน ZIP
- ฐาน dev `compound_qa_dev` แยกจาก production `compound_qa`
- สำรอง pg_dump ทุกชั่วโมงเป็น `.dump` เก็บล่าสุด 168 ไฟล์ใน `data/backups` หรือ `data-dev/backups`
- ต้องสำรองออกอีกดิสก์ด้วย และทดสอบกู้คืนก่อนใช้งานจริง

## เปิดอัตโนมัติเมื่อเปิดเครื่อง

หลังทดลอง START-SERVER.cmd สำเร็จ ให้ปิดโปรแกรมที่เปิดด้วยมือก่อน แล้วเปิด PowerShell แบบผู้ดูแลและรัน scripts/windows/INSTALL-AUTOSTART.ps1 จากโฟลเดอร์นี้

สคริปต์สร้างงานชื่อ COMPOUND-QA-Server ใน Windows Task Scheduler ให้รันเป็น SYSTEM ตอนเปิดเครื่อง ตั้งให้เริ่มใหม่เมื่อโปรแกรมล้ม และไม่ต้องให้ผู้ใช้เข้าสู่ Windows ก่อน ห้ามย้ายโฟลเดอร์ภายหลังโดยไม่ปรับงาน

การหยุด/เริ่มทำได้ใน Task Scheduler สคริปต์นี้ยังไม่ได้รันบนเครื่องปลายทาง คอมต้องไม่เข้า Sleep ระหว่างเวลาที่ต้องให้บริการ

## ผู้พัฒนา

Source อยู่ใน src/app/, src/features/, src/shared/ และ src/server/ ส่วนไฟล์รันที่สร้างจาก build อยู่ใน dist/

- npm install
- npm run build
- npm run typecheck
- npm test

dist/server/service.mjs และ dist/ เป็นผล build ที่จำเป็นต่อการรัน ต้อง build ใหม่หลังแก้ TypeScript หรือหน้าจอ การเพิ่ม schema ให้เพิ่ม migration ใหม่ใน migrations/ ห้ามแก้ migration ที่นำไปใช้แล้ว

ค่าทางเลือก: QA_PORT (เริ่มต้น 3000), QA_HOST (เริ่มต้น 0.0.0.0), QA_DATA_DIR และ QA_PUBLIC_URL เมื่อไม่มีการตั้ง URL ระบบแสดง IP ที่พบเพื่อช่วยทดสอบ แต่หัวหน้าต้องตรวจและตั้ง URL ถาวรก่อนพิมพ์ QR

ทดสอบบน Node.js 24 และ Chrome ทั้งหน้าจอ 1440×1050 และมือถือ 390×844 การติดตั้ง Task Scheduler, Firewall และทางเข้า HTTPS บนคอมอีกเครื่องยังต้องทดสอบที่เครื่องจริง

## ผลตรวจรุ่นส่งมอบ

ผ่าน automated tests 43 กรณี และทดสอบหน้าจอด้วย Chrome บนเซิร์ฟเวอร์ Windows/Node 24 รวมถึงบัญชี QA จริง สิทธิ์โรง/จุด การป้องกันส่งซ้ำ คิวออฟไลน์ PostgreSQL backup การรีสตาร์ต และการออกรายงานขณะปิดทุก browser

แตก ZIP ไปโฟลเดอร์ใหม่แล้วตรวจว่ารันได้โดยไม่มี node_modules และไม่มีบัญชีหรือฐานข้อมูลทดสอบติดไปด้วย ตรวจการปฏิเสธตั้งค่าผู้ดูแลผ่าน proxy และ redirect หลังเข้าสู่ระบบด้วย

ตรวจภาพหน้าจอผ่าน Chrome/Playwright ที่ 1440×1050 และ 390×844 เพราะไม่ได้ติดตั้ง Browser plugin เทียบกับแบบภาพในด้านการจัดวาง สีเขียว/คำเตือน ตัวอักษรไทยและตัวเลข ช่องกรอกพร้อมไม่เกี่ยวข้อง และปุ่มตรวจทานด้านล่าง การเพิ่มโรง/กะและหน้าบัญชีพนักงานเป็นส่วนที่เพิ่มตามการใช้งานจริง ไม่พบปัญหา runtime ในเส้นทางที่ทดสอบ

ยังต้องตรวจกล้อง QR โทรศัพท์จริง Task Scheduler/Firewall บนเครื่องปลายทาง และการเชื่อม HTTPS จากนอกโรงงานก่อนเริ่มหน้างาน

## QR แยกโรงและกะ

- เลือกโรงและกะในหน้า QR ประจำจุดก่อนพิมพ์ แต่ละชุดมี QR แยก 5 จุดตามแผน
- AJ2 กะเช้า, AJ2 กะดึก และ AJ2B กะเช้าเป็นคนละชุดกัน
- QR ระบุโรง + กะ + ไลน์ + จุดตรวจ โดยไม่ระบุชื่อพนักงานหรือวันที่
- สแกนแล้วเปิดฟอร์มทันทีและล็อกโรง/กะ ไม่ให้กดสลับโดยพลาด
- QR รุ่นเก่าที่ไม่มีข้อมูลกะต้องเปลี่ยนเป็นชุดใหม่ ระบบจะไม่เดากะจากค่าที่เคยเลือก
- สแกนนอกเวลากะแล้วไม่มีรอบที่เปิดอยู่ ระบบแสดงสถานะรอ โดยไม่สลับไปกะอื่น

## กรอกผลผลิตย้อนหลัง

- สแกน QR แล้วกด “เลือกวันที่ / รอบ เพื่อกรอกย้อนหลัง” ในหน้าฟอร์ม หรือกด “กรอกย้อนหลัง” จากหน้าหลัก
- เลือกวันที่ผลิตและรอบ 30 นาทีที่จบแล้ว โรง/กะยังล็อกตาม QR และใช้สิทธิ์จุดตรวจของบัญชีพนักงาน
- ถ้ามีรอบเดิม ใช้แผน/สเปกเดิมของรอบนั้น หากยังไม่มีรอบ ต้องตรวจและยืนยันแผนที่จะใช้ก่อนสร้าง
- กะดึกหลังเที่ยงคืนใช้วันที่เริ่มกะ ห้ามเลือกรอบในอนาคตหรือนอกช่วงกะ
- ระบบเก็บชื่อผู้กรอกกับเวลาที่ส่งจริง แก้ข้อมูลเดิมต้องระบุเหตุผลและเก็บประวัติ
- รายงานยังรอข้อมูลครบทุกจุด/ทุก SO และออกรายงานฉบับแก้ไขเมื่อมีการแก้ย้อนหลัง
- ออฟไลน์กรอกได้เฉพาะรอบเก่าที่เคยโหลดไว้ การสร้างรอบย้อนหลังใหม่ต้องเชื่อมต่อเซิร์ฟเวอร์

## ฟอร์มเตาอบบนมือถือ

- Burner 1 คือ SV อุณหภูมิที่ตั้ง (°C), Burner 2 คือ PV อุณหภูมิจริง (°C), ช่องที่ 3 คือเวลาอบแบบนาที.วินาที
- กรอกประจำรอบเพียง PV / น้ำหนัก Biscuit (กก.) / อุณหภูมิก้อนยาง (°C) แยกเตา A–D รวม 12 ช่อง
- มือถือเลือกแท็บเตา A–D และใช้ปุ่มเตาถัดไปที่แถบล่าง ส่วน desktop แสดงการ์ดครบทุกเตา
- SV และเวลาอบใช้ค่าปัจจุบัน ไม่ต้องกรอกซ้ำ ถ้าเปลี่ยนหน้างานให้กด “ปรับ SV / เวลาอบยาง” ของเตานั้น
- ค่าที่ปรับส่งต่อไปรอบถัดไปภายในโรง/กะ/ไลน์/ลูกค้า-SO เดิม ค่าที่วัดจริงจะว่างใหม่ทุกรอบ
- การปรับค่าตั้งบันทึกพร้อมข้อมูล QA แบบครั้งเดียว เก็บผู้กรอก เวลา และประวัติแก้ไข
- กรอกย้อนหลังไม่เขียนทับผลตรวจรอบอื่น และค่าตั้งที่ใหม่กว่าจะมีผลตามลำดับเวลาผลิต
- เปลี่ยน SV/เวลาในแผน หรือเปลี่ยนลูกค้า-SO จะเริ่มชุดค่าตั้งตามแผนใหม่
- ถ้าค่าตั้งเปลี่ยนจากอีกเครื่องระหว่างกรอก ต้องตรวจและใช้ค่าล่าสุดก่อนส่ง ค่าที่วัดจริงในร่างยังคงอยู่

## ฟอร์มหอโรย

- จุดเดิมชื่อ “เก๊ะ” เปลี่ยนชื่อแสดงเป็น “หอโรย” ข้อมูลเก่า สิทธิ์ และ QR เดิมยังเชื่อมจุดเดิม
- มือถือเลือกแท็บ ฝ่ายจักร / จุด A / จุด B / จุด C / จุด D / ล้าง-ซ่อม พร้อมสถานะกรอกครบและปุ่มจุดถัดไป
- desktop แสดงการ์ดทุกจุดในหน้าเดียว ใช้ช่องตัวเลขใหญ่และหน่วยเก๊ะ
- จำนวนเก๊ะเป็นสถานะ ณ จุดตรวจ ไม่รวมเข้า-หลัง-ออกเป็นยอดเคลื่อนย้าย
- กรอก 0 หรือเลือกไม่เกี่ยวข้องได้ แต่ช่องว่างไม่ถือว่าเป็น 0
- งานล้างกรอกเฉพาะจำนวน ไม่ต้องระบุหมายเลขเก๊ะ ส่วนงานซ่อมมากกว่า 0 ยังระบุหมายเลขเก๊ะที่ซ่อม
