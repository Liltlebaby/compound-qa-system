# ย้าย COMPOUND QA ไปคอมเซิร์ฟเวอร์ Windows

คู่มือนี้ใช้กับชุด `compound-qa-server-windows-x64.zip` สำหรับ Windows 10/11 แบบ 64 บิต มี Node.js 24 และ PostgreSQL 18 พร้อมใช้งาน ไม่ต้องติดตั้ง npm บนเครื่องเซิร์ฟเวอร์

## 1. เตรียมคอมเซิร์ฟเวอร์

1. แตก ZIP ไปที่ `C:\CompoundQA` หรือไดรฟ์ข้อมูลที่ฝ่าย IT จัดไว้ ใช้โฟลเดอร์ถาวร หลีกเลี่ยง OneDrive และไดรฟ์เครือข่าย
2. จำกัดสิทธิ์โฟลเดอร์นี้ให้ผู้ดูแลเซิร์ฟเวอร์และบัญชี SYSTEM เพราะจะมีข้อมูลและรหัสผ่านฐานข้อมูลอยู่ภายใน
3. ดับเบิลคลิก `SETUP-SERVER.cmd` เพื่อสร้างฐานข้อมูลและรหัสผ่านเฉพาะเครื่อง ไฟล์เดิมจะไม่ถูกเขียนทับ
4. หากขึ้นว่า PostgreSQL รันไม่ได้เพราะขาด DLL ให้ติดตั้ง `prerequisites\vc_redist.x64.exe` จาก Microsoft แล้วลองใหม่
5. ตั้ง IP คงที่หรือ DHCP reservation ให้คอมนี้ และตั้งเวลา Windows ให้ถูกต้อง ใช้เขตเวลา Bangkok หากใช้เวลาตามโรงงาน

ถ้ามี PostgreSQL อื่นใช้พอร์ต 5432 อยู่ ให้เปิด Command Prompt ในโฟลเดอร์นี้แล้วรัน `set QA_PG_PORT=55432` ตามด้วย `SETUP-SERVER.cmd` ก่อนติดตั้งครั้งแรก ห้ามคัดลอกโฟลเดอร์ `.postgres\data` จากอีกเครื่องขณะฐานข้อมูลทำงาน

## 2. ย้ายข้อมูลเดิม (ทำก่อน START ครั้งแรก)

ข้อมูลจริงเดิมใช้ฐานข้อมูล development ของเครื่องพัฒนา แม้หน้าเว็บจะเขียนว่า `mode=live` ส่วน `demo=1` เป็นข้อมูลตัวอย่างในเบราว์เซอร์และไม่รวมในไฟล์ย้าย

1. หยุดรับข้อมูลที่เครื่องเดิมชั่วคราวก่อนย้ายใช้งานจริง แล้วส่งออกข้อมูลล่าสุดอีกครั้งด้วยคำสั่งด้านล่าง
2. ย้าย ZIP ข้อมูลแยกต่างหาก `compound-qa-data-transfer.zip` มาที่เซิร์ฟเวอร์ แล้วแตกไฟล์ จะได้ `.dump` และ `.dump.json` คู่กัน
3. ลากไฟล์ `.dump` ไปวางบน `RESTORE-DATA.cmd` ระบบจะตรวจ SHA-256 และตรวจข้อมูลทุกตารางหลังนำเข้า ไม่เขียนทับฐานข้อมูลที่มีตารางอยู่แล้ว
4. บัญชี แผนผลิต ผลกรอก ประวัติ และรายงานเดิมจะย้ายมาด้วย แต่ session เดิมและ URL เซิร์ฟเวอร์เดิมจะถูกล้างเฉพาะสำเนาบนเครื่องใหม่ ต้องเข้าสู่ระบบใหม่และตั้ง URL ใหม่
5. เก็บไฟล์สำรองไว้ในพื้นที่จำกัดสิทธิ์ ห้ามอัปโหลดเข้า GitHub เพราะมีข้อมูล QA และข้อมูลบัญชี

ส่งออกข้อมูลจริงล่าสุดจากโฟลเดอร์โปรเจกต์บนเครื่องพัฒนา:

```bat
node dist\server-tools.mjs backup development C:\QA-Transfer
```

ต้องย้ายทั้งไฟล์ `.dump` และ `.dump.json` ที่ชื่อเดียวกัน ไฟล์ที่จัดให้เป็น snapshot ณ เวลาส่งออก ไม่รวมข้อมูลที่กรอกหลังจากนั้น ห้ามให้เครื่องเดิมและเครื่องใหม่รับข้อมูลจริงพร้อมกันหลังย้าย

## 3. เปิดระบบและมือถือ

1. กด `START-SERVER.cmd` แล้วเปิด `http://localhost:3000/?mode=live` จากคอมเซิร์ฟเวอร์ ระบบรันเบื้องหลัง ปิดหน้าต่างคำสั่งได้
2. หากเริ่มระบบใหม่โดยไม่ย้ายข้อมูล ให้สร้างบัญชีหัวหน้าครั้งแรกจาก localhost บนเซิร์ฟเวอร์เท่านั้น หากย้ายข้อมูลแล้วใช้บัญชีหัวหน้าเดิม
3. คลิกขวา `ENABLE-MOBILE-ACCESS.cmd` → Run as administrator เพื่อเปิดเฉพาะพอร์ตเว็บบนเครือข่าย Private ภายในโรงงาน ไม่เปิดพอร์ตฐานข้อมูล
4. มือถือเชื่อม Wi-Fi โรงงานเดียวกัน เปิด `http://IP-เซิร์ฟเวอร์:3000/?mode=live` เช่น `http://192.168.1.50:3000/?mode=live` คำว่า localhost บนมือถือหมายถึงมือถือเอง
5. หัวหน้าตั้ง URL นี้ในหน้าตั้งค่า แล้วสร้างและพิมพ์ QR ใหม่ตามโรง/กะ/ฝ่าย ทดสอบสแกนทุกจุดก่อนติดหน้างาน QR ที่ชี้ IP เครื่องเดิมต้องเปลี่ยน
6. คลิกขวา `INSTALL-AUTOSTART.cmd` → Run as administrator เพื่อติดตั้ง Task Scheduler `COMPOUND-QA-Server` เปิดพร้อม Windows แล้วทดสอบรีสตาร์ตเครื่องหนึ่งครั้ง

ถ้า PowerShell ถูกนโยบายองค์กรบล็อก ให้ IT ตรวจและอนุมัติสคริปต์ใน `scripts\windows` ก่อนใช้งาน ไม่ต้องปิดระบบป้องกันของเครื่อง การติดตั้ง Task Scheduler และ firewall ยังต้องทำบนเครื่องปลายทาง ไฟล์ชุดนี้ไม่เปลี่ยนค่าเครื่องพัฒนาให้เอง

## 4. ใช้นอกโรงงาน / HTTPS

รุ่นนี้เตรียมการรันใน LAN ก่อน ยังไม่มีโดเมนหรือ HTTPS สาธารณะ ให้ IT ทำ VPN หรือ HTTPS reverse proxy / tunnel แบบมีโดเมนถาวรและควบคุมสิทธิ์ แล้วตั้ง Public URL และพิมพ์ QR ใหม่ ดูรายละเอียดใน [docs/HTTPS-ACCESS.md](docs/HTTPS-ACCESS.md)

ไม่ควร forward พอร์ต PostgreSQL 5432 ออกอินเทอร์เน็ต ปุ่ม QR เข้าบัญชีแต่ละฝ่ายได้ตามที่กำหนด จึงควรเก็บ QR ไว้เฉพาะผู้เกี่ยวข้องและจำกัดเครือข่ายที่เข้าระบบได้

## 5. สำรองข้อมูลและตรวจประจำวัน

- กด `BACKUP-DATA.cmd` เพื่อสร้าง `.dump` พร้อม manifest ที่ `data\backups\manual` ระบบมีสำรองรายชั่วโมงเดิมที่ `data\backups\postgres` ด้วยเมื่อมีบัญชีหัวหน้า
- คัดลอกสำรองไปอีกอุปกรณ์หรือพื้นที่สำรองของบริษัทอย่างน้อยวันละครั้ง ทดสอบกู้คืนเป็นระยะ สำรองในดิสก์เดียวกันอย่างเดียวไม่พอ
- เก็บ `.env.production.local` และ `.postgres\local.json` ไว้ในพื้นที่สำรองจำกัดสิทธิ์ ห้ามใส่ GitHub
- กด `STOP-SERVER.cmd` เพื่อหยุดเว็บอย่างถูกจุด PostgreSQL ยังคงทำงานอยู่ ถ้าจะย้ายโฟลเดอร์ให้หยุด Task Scheduler และรัน `runtime\node.exe dist\postgres-local.mjs stop` ก่อน
- ดูข้อผิดพลาดเว็บที่ `data\logs\server.log` และฐานข้อมูลที่ `.postgres\postgres.log`

## 6. อัปเดตจาก GitHub แบบกดเอง

Repository ส่วนตัว: [Liltlebaby/compound-qa](https://github.com/Liltlebaby/compound-qa)

**ที่เครื่องพัฒนา:** แก้โค้ด → รัน `npm run check` → commit/push → สร้าง tag รุ่นถัดไป เช่น `v1.0.2` แล้ว push tag GitHub Actions จะทดสอบและสร้าง Release ที่มี `compound-qa-update.zip` และ `.sha256` ควรรอ Actions ผ่านก่อนนำไปใช้

```bat
git add .
git commit -m "Describe the change"
git push origin main
git tag v1.0.2
git push origin v1.0.2
```

**ที่เครื่องเซิร์ฟเวอร์:** กด `CONNECT-GITHUB.cmd` ครั้งแรก แล้วเข้าสู่ GitHub ด้วยบัญชีที่อ่าน private repo นี้ได้ จากนั้นเวลาจะอัปเดตให้กด `UPDATE-SERVER.cmd` ไม่อัปเดตเองระหว่างทำงาน ถ้า GitHub CLI เปิดขั้นตอน device code ให้ยืนยันเองในเว็บไซต์ GitHub ไม่ส่ง token ผ่านแชต

ตัวอัปเดตดาวน์โหลด Release ล่าสุด ตรวจ checksum หยุดเว็บชั่วคราว สำรองข้อมูล กู้สำเนาฐานข้อมูลไปฐานใหม่ ทดสอบ migration และหน้าเว็บก่อนสลับไปใช้รุ่นใหม่ ถ้าล้มเหลวจะกลับไปโปรแกรมและฐานข้อมูลเดิม ไม่ลบฐานข้อมูลเก่า เลือกช่วงพักงานและให้ QA ส่งแบบร่างค้างให้เรียบร้อยก่อนอัปเดต

กรณีเซิร์ฟเวอร์ไม่ออกอินเทอร์เน็ต ให้ดาวน์โหลด ZIP อัปเดตและ `.sha256` คู่กันมาวางโฟลเดอร์เดียวกัน แล้วลาก ZIP ลงบน `UPDATE-SERVER.cmd` ไม่ต้องเชื่อม GitHub บนเซิร์ฟเวอร์

ชุดอัปเดตมีเฉพาะโปรแกรม ไม่ทับ `data`, `.env*`, `.postgres` หรือ runtime เครื่องเซิร์ฟเวอร์ไม่ต้อง `git pull` หรือ `npm install` รหัสผ่าน GitHub ใช้ที่เก็บ credential ของ GitHub CLI ของบัญชี Windows ผู้กดอัปเดต ห้ามคัดลอก token เข้าโปรเจกต์

## 7. เมื่ออัปเดตถูกขัดจังหวะ / ไฟดับ

ปกติถ้าอัปเดตล้มเหลวระบบจะคืนรุ่นเดิมเอง หากมี `data\maintenance.lock` ค้างหลังไฟดับ ระบบจะไม่เปิดเว็บอัตโนมัติเพื่อป้องกันเปิดชุดโปรแกรมที่คัดลอกไม่ครบ ให้ IT ตรวจโฟลเดอร์ที่ระบุใน lock และ `data\rollback\วันที่เวลา`:

1. หยุด Task Scheduler `COMPOUND-QA-Server` และ `STOP-SERVER.cmd`
2. เก็บสำเนาทั้งโฟลเดอร์ก่อนแก้ไข
3. คืน `code` จากโฟลเดอร์ rollback ไปทับไฟล์โปรแกรม และคืน `environment.local` เป็น `.env.production.local` เพื่อจับคู่โปรแกรมกับฐานข้อมูลเดิม
4. ย้าย `maintenance.lock` ไปเก็บเป็นหลักฐาน แล้วเริ่มระบบ ตรวจข้อมูลก่อนเปิดรับงาน

หลังอัปเดตสำเร็จ หากต้องย้อนรุ่น ให้หยุดรับงานและสำรองข้อมูลปัจจุบันก่อน การคืนฐานข้อมูลรุ่นก่อนจะไม่รวมรายการที่กรอกหลังอัปเดต จึงต้องให้ IT ประเมินและย้ายรายการเหล่านั้นด้วย ห้ามลบฐาน `qa_release_*` หรือโฟลเดอร์ rollback จนกว่าจะตรวจรับและมีสำรองภายนอกแล้ว

## ก่อนเริ่มนำร่อง

ทดสอบบนมือถือจริงอย่างน้อย 2 เครื่อง: สแกนถูกโรง/กะ/ฝ่าย กรอกแล้วอีกเครื่องเห็นโดยไม่รีเฟรช แบบร่างเน็ตหลุดไม่หาย ค่าผิดเกณฑ์ขึ้น Alarm เตาปิดไม่บังคับกรอก รายงานรอทุกจุดครบ แชร์ WhatsApp ได้ และรีสตาร์ตเซิร์ฟเวอร์แล้วข้อมูลยังอยู่

รุ่นนี้ตรวจข้อมูลและสรุปตามกฎ ยังไม่เชื่อม AI และยังใช้ปุ่มแชร์ WhatsApp ให้หัวหน้ายืนยันส่งเอง
